# Optional fixed-stat test pin

`admin grant-test-pin` creates a **new** Rustic but Precious Pin variant. It
preserves the original pin and existing inventory. This is an opt-in PowerShell
command; pulling the code alone generates no items or account-specific static
changes. It requires matching external 3.57.0 EU reference data containing the
pin. [Currency administration](administration.md) uses separate commands.

## Grant

Close Guardian Tales and stop the backend with Ctrl+C first. Keep the same
working state directory; CDN and bridge can remain open. From the repository
root, grant a pin with **10,000 base DEF**:

```powershell
.\.venv\Scripts\python.exe -m guardian_tales admin grant-test-pin --data-dir local/state --reference-dir local/client-data/reference --operation-id pin-test-001 --reason "Local testing"
```

For an optional **ATK +1000% suboption**, append `--attack-percent 1000` to that
command **before its first execution**. This uses the client's ordinary ATK
percent option (option 10), replacing the original static ATK +4.1% bonus on the
new variant. Its original DEF/HP +4.1% static bonuses remain. Without the flag,
it retains all three original static bonuses and has no random suboptions.
ATK percent is additive with other attack bonuses; it does not promise a fixed
multiplier to final combat damage.

The new equipment starts at level 1 with no limit breaks and is locked. Its
separate definition sets base DEF directly and growth to 1.0, so it does not
use an out-of-range DEF-percent option. It retains the original sprite and
localized name. `--defense` accepts integers 1..10000 (default 10000), and
`--attack-percent` accepts 0..1000 (default 0). The suboption's definition has a
fixed range matching the requested value. General enhancement, rerolling,
engraving, evolution and extraction of the variant are outside this command's
scope; it is intended for equipping and combat experiments.

The result includes inventory/spec IDs and the backup path. Every new grant or
retirement makes a coherent SQLite backup with an adjacent SHA-256 file in the
selected state directory's `backups` folder before writing. Profile, definition
and receipt commit together. Only the appended row, allocation counter and user
revision change; currencies, original gear, imported seeds and other saved
progress stay intact. Restart the backend with its usual arguments and reopen
the game to load the variant.

Repeating the same operation ID, reason and parameters returns `already_applied`
without adding another item or restoring one already sold/retired. Conflicting
parameters reject. Use a new operation ID only for an intentional additional
pin. The bounded registry retains up to 256 grant receipts per account.

## History and removal

Read the private receipts, including whether each pin is still present:

```powershell
.\.venv\Scripts\python.exe -m guardian_tales admin test-pin-history --data-dir local/state
```

To retire **only the pin generated by that operation**, close the game and stop
the backend, then run:

```powershell
.\.venv\Scripts\python.exe -m guardian_tales admin remove-test-pin --data-dir local/state --operation-id pin-test-001
```

Retirement works while locked and clears ordinary character slots holding the
item. Remove preset/Training Room assignments and socketed jewels first; these
remain protected. It preserves later progress and never rolls the whole account
back. It is idempotent, including when the generated item was already sold.
The backend's existing unlock/sell routes accept the new equipment and credit
zero gold; native sell-button availability is still an APK verification item.
This legend-rarity pin is not eligible for epic extraction.

Generated definitions/receipts remain inside the private account database. The
updated backend composes only currently owned variants over the effective
Raid/Arena/Guild War and nickname static tables, with new checksums, without
editing reference/resource files. Removing all generated pins restores the
normal parent static response. Keep the updated backend while generated items
exist; retire them before returning to a revision without this feature.

## Verification

Twenty Windows regressions cover grant/removal, backups, imported-account
preservation, allocation, retries, rollback, state locking, ordinary sale and
static composition/checksum refresh. A separate isolated copy of the working
account passed grant, static delivery/check-update and targeted retirement,
preserving its original inventory and all 65 other tables with zero source
writes. Native inspection supports the base-defense calculation, ATK option and
reuse of the localized name. **Appearance, equipping, combat effect and
persistence in the actual APK remain pending.**
